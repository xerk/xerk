I spent years writing PHP and Laravel before Node took over my life, and I keep noticing the same thing. Laravel ships primitives that Node developers end up rebuilding by hand, over and over.

## Debounced listeners: one config line versus forty

This month Laravel shipped debounced queued event listeners. You add one config and you're done.

In Node land I have written that debounce logic myself at least four times: a Redis key, a TTL, a timer, and the edge cases for when the process dies mid window. It comes to around 40 lines that every team writes slightly differently, and slightly wrong. Those edge cases are where the bugs live.

## Locks: a fluent builder versus a wiki page

The new Laravel Lock package is the same story. You get distributed locks scoped to models and routes, with a fluent builder.

In Node that's redlock, plus conventions you have to invent, plus a wiki page nobody reads.

## Why I am still on Node

I'm not going back to PHP. Node's ecosystem won me over for other reasons, and the async model fits what I build.

The difference in framework culture is real, though. Laravel decides, ships and documents. Node gives you seventeen npm packages and a debate.

Some days I want the debate. Most days I want the config line. What I miss most, if I'm honest, is `php artisan`, all of it.
